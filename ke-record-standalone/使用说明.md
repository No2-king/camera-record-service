# 录像下载服务（独立包）

一个**自包含**的摄像头/NVR 历史录像下载服务。
解压到任意目录 → 双击一个 BAT → 完成。不需要装 Node、不需要装 ffmpeg、不需要联网。

---

## 一、这个包能做什么

提供 HTTP 接口，把海康设备（NVR / 带存储的摄像头）上**指定时间段的历史录像**取下来，转成标准 mp4：

```
查有没有录像 → 发起下载 → 轮询进度 → 下载 mp4 文件
```

- 端口：**3001**
- 服务名：**KE-RecordService**
- 零第三方 npm 依赖（只用 Node 内置模块）

---

## 二·五、Node.js 运行时从哪来

安装脚本不写死 node 路径，交给 `_find-node.bat` 按顺序查找：

1. 系统 `PATH` 中的 `node` —— **本机装过就直接用**
2. 常见安装目录 —— `Program Files\nodejs`、nvm 的 `NVM_SYMLINK`、`LOCALAPPDATA\Programs\nodejs`
3. 包内 `nodejs\node.exe` —— 本机没装时的兜底

本机装了 Node，就不需要包里的 `nodejs\` 目录；没装才用包内自带的。
两者都没有时，安装脚本会列出已尝试的位置和两种解决办法。

单独查看解析结果：`_find-node.bat verbose`

## 三、安装（2 步）

### 第 ① 步：安装服务

右键 `install-service.bat` → **以管理员身份运行**

脚本自动完成：

1. 检查文件完整性
2. 注册 `FFMPEG_PATH` 环境变量（指向包内 `tools\ffmpeg.exe`）
3. 注册 `KE-RecordService` 服务（开机自启、崩溃自动重启）
4. 启动服务

看到 `STATE : 4 RUNNING` 就成功了。

### 第 ② 步：放行防火墙（局域网访问时才需要）

右键 `firewall-rules.bat` → **以管理员身份运行**

> 只在本机用 `localhost:3001` 的话，这步可以跳过。

### 验证

浏览器打开 `http://localhost:3001/health`，看到：

```json
{
  "success": true,
  "service": "record-service",
  "port": 3001,
  "ffmpegAvailable": true
}
```

`ffmpegAvailable: true` 就说明环境完全就绪。

### 打开本地调试页面

双击 `start-web.bat` —— 自动启动本地网页服务并打开浏览器，页面上可以：

- 填写设备参数，**查询某时间段有没有录像**（不用记 curl 命令）
- **发起下载并实时看进度条**，完成后一键保存 mp4
- 查看历史任务列表

页面**不依赖外网**（没有任何 CDN 资源，完全离线可用），关掉黑窗口即停止。

> 独立包只装了下载服务，所以页面顶部 **WebRTC 和 ONVIF-PTZ 两个状态灯会显示"失败"**，
> 这属于正常现象 —— 录像下载功能照常可用。装了完整套件包则三个都是绿的。

## 四、接口一览

> 完整的参数说明、响应字段表、错误码、状态机、前端封装示例，见 **`接口文档.md`**。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 服务信息页（浏览器直接打开） |
| GET | `/health` | 健康检查，含 ffmpeg 可用性 |
| POST | `/search` | 查某时间段有没有录像 |
| POST | `/download` | 发起下载，立即返回 `taskId` |
| GET | `/progress?taskId=` | 查询任务进度 |
| GET | `/file?name=` | 下载成品 mp4 |
| GET | `/tasks` | 任务列表 |
| DELETE | `/task?id=` | 删除任务 + 它的成品 mp4 |

> 成品默认保留 **7 天**（按发起下载的时间算），到期自动删任务和文件；
> 也可以随时 `DELETE /task?id=` 手动删。任务表落盘在 `downloads/tasks.json`，
> 服务重启不会丢。

### 请求参数

| 参数 | 必填 | 说明 |
|---|:---:|---|
| `cameraIp` | ✅ | 设备 IP（也可传 `xaddr`，会自动提取 IP） |
| `isapiPort` | | ISAPI 端口，**默认 80**。海康的 ISAPI 与 ONVIF **共用同一个 HTTP 端口**，填成和 ONVIF 端口一致即可 |
| `userName` | ✅ | 用户名（兼容 `username`） |
| `password` | ✅ | 密码（兼容 `pass`） |
| `channel` | | 通道号，从 1 开始，默认 1 |
| `stream` | | `main`（主码流，默认）/ `sub`（子码流，体积小很多） |
| `start` | ✅ | 开始时间，**本地时间**，格式 `2026-10-15 08:00:00` |
| `end` | ✅ | 结束时间，同上 |
| `tz` | | 时区偏移，默认 `0` = **不换算**（填几点就按几点发给设备） |

> 时间填**本地时间**即可，服务内部自动转 UTC。填错时区是搜不到录像的头号原因。

## 五、完整调用示例

### 第一步：确认有没有录像

```bash
curl -X POST http://localhost:3001/search -H "Content-Type: application/json" ^
  -d "{\"cameraIp\":\"192.168.1.100\",\"isapiPort\":80,\"userName\":\"admin\",\"password\":\"xxx\",\"channel\":1,\"start\":\"2026-10-15 08:00:00\",\"end\":\"2026-10-15 09:00:00\"}"
```

```json
{
  "success": true,
  "count": 2,
  "segments": [
    { "start": "2026-10-15T00:00:00Z", "end": "2026-10-15T00:30:00Z" },
    { "start": "2026-10-15T00:30:00Z", "end": "2026-10-15T01:00:00Z" }
  ]
}
```

`count` 为 0 就是那段时间没录像。

### 第二步：发起下载

```bash
curl -X POST http://localhost:3001/download -H "Content-Type: application/json" ^
  -d "{\"cameraIp\":\"192.168.1.100\",\"isapiPort\":80,\"userName\":\"admin\",\"password\":\"xxx\",\"channel\":1,\"start\":\"2026-10-15 08:00:00\",\"end\":\"2026-10-15 09:00:00\"}"
```

```json
{ "success": true, "taskId": "a1b2c3d4", "status": "queued" }
```

### 第三步：轮询进度

```bash
curl "http://localhost:3001/progress?taskId=a1b2c3d4"
```

```json
{
  "success": true,
  "status": "running",
  "percent": 45,
  "message": "下载第 2/4 段",
  "file": null
}
```

`status`：`queued` → `running` → `done` / `failed`

### 第四步：取文件

```bash
curl -O -J "http://localhost:3001/file?name=ch1_20261015_080000_090000.mp4"
```

成品同时也会落在 `record-service\downloads\` 目录里，可以直接去那儿拿。

## 六、前端调用参考

```js
// 发起下载
const res = await fetch('http://localhost:3001/download', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    cameraIp: '192.168.1.100',
    isapiPort: 80,
    userName: 'admin',
    password: 'xxx',
    channel: 1,
    start: '2026-10-15 08:00:00',
    end: '2026-10-15 09:00:00',
  }),
});
const { taskId } = await res.json();

// 轮询进度
const timer = setInterval(async () => {
  const p = await (await fetch(`http://localhost:3001/progress?taskId=${taskId}`)).json();
  console.log(p.percent + '%', p.message);

  if (p.status === 'done') {
    clearInterval(timer);
    location.href = `http://localhost:3001/file?name=${encodeURIComponent(p.file)}`;
  }
  if (p.status === 'failed') {
    clearInterval(timer);
    console.error('失败:', p.error);
  }
}, 1500);
```

服务已开 CORS（`Access-Control-Allow-Origin: *`），前端可直接跨域调用。

## 七、工作原理

```
① 查录像段   POST /ISAPI/ContentMgmt/search    → 拿到 playbackURI 列表
② 下载流     POST /ISAPI/ContentMgmt/download  → 海康私有 PS 流
③ 转 mp4     ffmpeg -i xxx.ps -c copy xxx.mp4
④ 多段合并   ffmpeg -f concat ... -c copy final.mp4
⑤ 返回文件   GET /file?name=xxx.mp4
```

跨多个录像段时会自动合并成一条完整视频。同时最多跑 2 个下载任务。

## 八、环境变量（可选，一般不用改）

| 变量 | 默认 | 说明 |
|---|---|---|
| `FFMPEG_PATH` | 包内 `tools\ffmpeg.exe` | ffmpeg 位置（安装脚本自动写） |
| `RECORD_PORT` | 3001 | 监听端口 |
| `RECORD_DIR` | `record-service\downloads` | 成品输出目录 |
| `RECORD_TZ` | `0` | 默认时区偏移，`0` = 不换算 |
| `RECORD_CONCURRENCY` | 2 | 同时下载任务数 |

要改的话，编辑 `install-service.bat` 里的 `AppEnvironmentExtra` 一行，然后重跑安装脚本。

> **为什么 ffmpeg 必须放包内**：服务由 NSSM 以 `LocalSystem` 身份启动，
> 看不到"用户级"PATH。即使系统里装了 ffmpeg，服务也可能找不到。包内自带最稳。

## 九、常见问题

**服务启动后立即停止？**

看 `record-service\logs\stderr.log`。多半是端口被占：`netstat -ano | findstr :3001`

**提示"该时间段没有录像"？**

依次排查：
1. 时间填的是不是**设备上显示的时间**（服务不换算时区，填几点就找几点）
2. 设备有没有配录像计划、录像是否已被循环覆盖
3. `isapiPort` 填对没有——它应与设备的 HTTP / ONVIF 端口一致（出厂默认 80）
4. `channel` 对不对

**提示"无法连接设备"？**

- `ping` 一下 `cameraIp`
- 换个 `isapiPort` 试（80 / 8000）
- 确认账号有回放权限

**`/health` 里 `ffmpegAvailable` 是 false？**

`tools\ffmpeg.exe` 不存在。放一个进去，或设 `FFMPEG_PATH`，然后重启服务。

**包太大？**

`tools\ffmpeg.exe` 占 212MB（full build）。换成 [essentials 版](https://www.gyan.dev/ffmpeg/builds/)（约 90MB）功能完全够用。

**换了机器 / 换了目录？**

整个文件夹复制过去，重新跑 `install-service.bat` 即可。脚本会自动用新路径覆盖旧的服务注册和环境变量。

## 十、卸载

右键 `uninstall-service.bat` → **以管理员身份运行**

只删除服务注册和 `FFMPEG_PATH` 环境变量，**不删除任何程序文件**。
想彻底清理，直接删掉整个文件夹。

## 十二、和「完整套件包」的关系

| 包 | 服务 | 端口 |
|---|---|---|
| **ke-camera-suite**（完整套件） | KE-WebRTCStreamer | 8000 |
| | KE-OnvifPtzService | 3000 |
| | KE-RecordService | 3001 |
| **ke-record-standalone**（本包） | KE-RecordService | 3001 |

两个包里的下载服务**是同一个东西，服务名也相同**，所以：

- 只装本包 → 只有下载功能
- 只装完整套件 → 播放 + 云台 + 下载
- **两个都装 → 后装的那个会覆盖 `KE-RecordService`**，两个包的下载服务不会共存

如果已经装了完整套件，就不需要再装本包了。
