# 录像下载服务 · 接口文档

| 项目 | 说明 |
|---|---|
| 服务名 | `KE-RecordService` |
| 默认端口 | **3001** |
| 协议 | HTTP/1.1 |
| 编码 | UTF-8 |
| 数据格式 | JSON（请求与响应） |
| 依赖 | 无第三方 npm 包 |

适用于 `ke-camera-suite`（完整套件）和 `ke-record-standalone`（独立下载服务）两个包 ——
两边的下载服务是**同一份代码、同一套接口**。

---

## 一、Base URL

```
http://<服务器IP>:3001
```

本机调试用 `http://localhost:3001`。

---

## 二、通用约定

### 2.1 请求头

POST 接口必须带：

```http
Content-Type: application/json
```

### 2.2 跨域（CORS）

服务已全局开启 CORS，前端可跨域直接调用：

```http
Access-Control-Allow-Origin: *
Access-Control-Allow-Headers: Content-Type
Access-Control-Allow-Methods: GET,POST,OPTIONS
```

预检请求（`OPTIONS`）返回 `204`。

### 2.3 时间格式 ⚠️

**所有时间参数都填「设备所在地的本地时间」，不是 UTC。**

```
格式:  YYYY-MM-DD HH:MM:SS
示例:  2026-10-15 08:00:00
```

也可以只写到分钟（`2026-10-15 08:00`，秒默认补 `00`），或用 `T` 分隔（`2026-10-15T08:00:00`）。

时区由 `tz` 参数指定，**默认 `8`（北京时间）**。服务内部会自动减去时区偏移转成 UTC 再请求设备。

> **填错时间是搜不到录像的头号原因。** 如果设备在别的时区，务必显式传 `tz`。

### 2.4 响应结构

**成功**

```json
{ "success": true, ...业务字段 }
```

**失败**

```json
{ "success": false, "error": "错误描述" }
```

### 2.5 设备参数（`/search` 与 `/download` 共用）

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|:---:|---|---|
| `cameraIp` | string | ✅ | — | 设备 IP，如 `192.168.1.100` |
| `xaddr` | string | — | — | ONVIF 地址。**不传 `cameraIp` 时**会从中自动提取 IP，如 `http://192.168.110.11:9080/onvif/device_service` |
| `isapiPort` | number | | `80` | ISAPI 端口 |
| `userName` | string | ✅ | — | 用户名（兼容 `username`） |
| `password` | string | ✅ | — | 密码（兼容 `pass`） |
| `channel` | number | | `1` | 通道号，从 1 开始 |
| `stream` | string | | `main` | `main` 主码流 / `sub` 子码流 |
| `start` | string | ✅ | — | 开始时间（本地时间） |
| `end` | string | ✅ | — | 结束时间（本地时间），必须晚于 `start` |
| `tz` | number | | `8` | 时区偏移小时数 |

> **`isapiPort` 说明**：海康设备的 **ISAPI 与 ONVIF 共用同一个 HTTP 端口**（出厂默认 `80`）。
> 也就是说，ONVIF 地址里的端口是多少，这里就填多少 —— 两者**不应该是不同的值**。
> 只有当设备的 HTTP 端口被改过（例如改成 `9080`）时，才需要显式指定。

## 三、接口详情

### 3.1 `GET /health` — 健康检查

**请求**

```http
GET /health
```

无参数。

**响应字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `success` | boolean | 固定 `true` |
| `service` | string | 固定 `record-service` |
| `port` | number | 监听端口 |
| `outDir` | string | 成品输出目录的绝对路径 |
| `ffmpegPath` | string | 实际使用的 ffmpeg 路径 |
| `ffmpegAvailable` | boolean | **ffmpeg 是否可用，false 说明下载功能不可用** |
| `running` | number | 正在执行的任务数 |
| `queued` | number | 排队中的任务数 |
| `tasks` | number | 内存中保留的任务总数 |

**响应示例**

```json
{
  "success": true,
  "service": "record-service",
  "port": 3001,
  "outDir": "C:\\ke-record-standalone\\record-service\\downloads",
  "ffmpegPath": "C:\\ke-record-standalone\\tools\\ffmpeg.exe",
  "ffmpegAvailable": true,
  "running": 0,
  "queued": 0,
  "tasks": 0
}
```

**用途**：部署后第一件事就是访问它，`ffmpegAvailable: true` 说明环境完全就绪。

### 3.2 `POST /search` — 查询录像段

先确认某个时间段**到底有没有录像**，再决定下不下载。

**请求**

```http
POST /search
Content-Type: application/json
```

```json
{
  "cameraIp": "192.168.1.100",
  "isapiPort": 80,
  "userName": "admin",
  "password": "admin123",
  "channel": 1,
  "start": "2026-10-15 08:00:00",
  "end": "2026-10-15 09:00:00"
}
```

参数见 [2.5 设备参数](#25-设备参数search-与-download-共用)。

**响应字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `success` | boolean | 是否成功 |
| `count` | number | 该时间段内的录像段数量 |
| `segments` | array | 录像段列表，元素见下 |
| `hint` | string | 仅在 `count` 为 `0` 时出现，提示可能的原因 |

**`segments` 元素**

| 字段 | 类型 | 说明 |
|---|---|---|
| `start` | string | 段起始时间（**UTC**，ISO 格式） |
| `end` | string | 段结束时间（**UTC**，ISO 格式） |

**成功响应示例**

```json
{
  "success": true,
  "count": 2,
  "segments": [
    { "start": "2026-10-15T00:00:00Z", "end": "2026-10-15T00:30:00Z" },
    { "start": "2026-10-15T00:30:00Z", "end": "2026-10-15T01:00:00Z" }
  ]
}
```

> 北京时间 `08:00` 对应 UTC `00:00`，所以返回的是 `T00:00:00Z`。

**没有录像时**

```json
{
  "success": true,
  "count": 0,
  "segments": [],
  "hint": "该时间段没有录像（未配置录像计划 / 已被循环覆盖 / 时间写错）"
}
```

**错误响应**

| 状态码 | 场景 | 示例 |
|---|---|---|
| `400` | 参数缺失或非法 | `{"success":false,"error":"缺少 cameraIp 或 xaddr"}` |
| `502` | 与设备通信失败 | `{"success":false,"error":"connect ECONNREFUSED 192.168.1.100:80"}` |

### 3.3 `POST /download` — 发起下载

**异步接口**：立即返回 `taskId`，实际下载在后台排队执行。用 `/progress` 轮询进度。

**请求**

```http
POST /download
Content-Type: application/json
```

```json
{
  "cameraIp": "192.168.1.100",
  "isapiPort": 80,
  "userName": "admin",
  "password": "admin123",
  "channel": 1,
  "stream": "main",
  "start": "2026-10-15 08:00:00",
  "end": "2026-10-15 09:00:00"
}
```

参数与 `/search` **完全一致**（见 2.5）。

**响应字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `success` | boolean | 是否成功受理 |
| `taskId` | string | 任务 ID，8 位十六进制，用于查询进度 |
| `status` | string | 初始状态，固定 `queued` |

**响应示例**

```json
{
  "success": true,
  "taskId": "a1b2c3d4",
  "status": "queued"
}
```

**错误响应**

| 状态码 | 场景 |
|---|---|
| `400` | 参数缺失或非法（此时不会创建任务） |

> ⚠️ **`/download` 返回成功只代表任务已受理**，不代表下载成功。
> 设备连不上、那段时间没录像等问题，会体现在 `/progress` 的 `status: "failed"` 里。

---

### 3.4 `GET /progress` — 查询任务进度

**请求**

```http
GET /progress?taskId=a1b2c3d4
```

**查询参数**

| 参数 | 必填 | 说明 |
|---|:---:|---|
| `taskId` | ✅ | `/download` 返回的任务 ID |

**响应字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `success` | boolean | 任务是否存在 |
| `taskId` | string | 任务 ID |
| `status` | string | `queued` / `running` / `done` / `failed` |
| `percent` | number | 进度百分比 `0`–`100` |
| `message` | string | 当前阶段的文字描述 |
| `file` | string \| null | 完成后为成品文件名，否则 `null` |
| `size` | number | 成品字节数，未完成时为 `0` |
| `segments` | number | 本次涉及的录像段数量 |
| `error` | string \| null | 失败原因，成功时为 `null` |

**进行中**

```json
{
  "success": true,
  "taskId": "a1b2c3d4",
  "status": "running",
  "percent": 45,
  "message": "下载第 2/4 段",
  "file": null,
  "size": 0,
  "segments": 4,
  "error": null
}
```

**已完成**

```json
{
  "success": true,
  "taskId": "a1b2c3d4",
  "status": "done",
  "percent": 100,
  "message": "完成",
  "file": "ch1_20261015_080000_090000.mp4",
  "size": 157286400,
  "segments": 4,
  "error": null
}
```

**已失败**

```json
{
  "success": true,
  "taskId": "a1b2c3d4",
  "status": "failed",
  "percent": 2,
  "message": "正在搜索录像段",
  "file": null,
  "size": 0,
  "segments": 0,
  "error": "该时间段没有录像（未配置录像计划 / 已被循环覆盖 / 时间写错）"
}
```

**任务不存在**

```http
HTTP/1.1 404 Not Found
```

```json
{ "success": false, "error": "任务不存在或已过期" }
```

> 已完成/失败的任务会在 **2 小时**后被自动清理，之后查询返回 404。

### 3.6 `GET /file` — 下载成品文件

**请求**

```http
GET /file?name=ch1_20261015_080000_090000.mp4
```

**查询参数**

| 参数 | 必填 | 说明 |
|---|:---:|---|
| `name` | ✅ | 成品文件名（从 `/progress` 或 `/tasks` 的 `file` 字段获取） |

**成功响应**

```http
HTTP/1.1 200 OK
Content-Type: video/mp4
Content-Length: 157286400
Content-Disposition: attachment; filename="ch1_20261015_080000_090000.mp4"
```

响应体是**二进制文件流**，可直接用浏览器打开链接触发下载。

**错误响应**

| 状态码 | 场景 |
|---|---|
| `404` | 文件不存在 / 文件名不合法 |

```json
{ "success": false, "error": "文件不存在" }
```

> **安全说明**：文件名只允许 `A-Z a-z 0-9 _ . -`，
> 含路径分隔符或其它字符会被拒绝，防止目录穿越。

### 3.8 `POST /deviceinfo` — 设备型号（自检）

确认"对面到底是什么设备"。**不需要 `start` / `end`**。

```bash
curl -X POST http://localhost:3001/deviceinfo -H "Content-Type: application/json" ^
  -d "{\"cameraIp\":\"192.168.1.100\",\"isapiPort\":80,\"userName\":\"admin\",\"password\":\"admin123\"}"
```

参数：`cameraIp`（必填，也可用 `host` / `xaddr`）、`isapiPort`（默认 `80`）、`userName`、`password`。

```json
{
  "success": true,
  "device": "192.168.1.100",
  "name": "IP Camera",
  "model": "DS-2CD3T47EWD-L",
  "serial": "DS-2CD3T47EWD-L20200101AAWR12345678",
  "firmware": "V5.7.3 build 210123"
}
```

| 字段 | 说明 |
|---|---|
| `model` | 设备型号 —— **`DS-` 开头是海康**；其它前缀说明不是海康，ISAPI 未必支持 |
| `firmware` | 固件版本，老固件的 ISAPI 返回结构可能不同 |

### 3.9 `POST /storage` — 存储介质状态（自检）⭐

**排查「查不到录像」的第一站。** 直接问设备：你有没有地方存录像？

同样**不需要** `start` / `end`，参数与 `/deviceinfo` 一致。

```bash
curl -X POST http://localhost:3001/storage -H "Content-Type: application/json" ^
  -d "{\"cameraIp\":\"192.168.1.100\",\"isapiPort\":80,\"userName\":\"admin\",\"password\":\"admin123\"}"
```

**设备有存储**

```json
{
  "success": true,
  "device": "192.168.1.100",
  "count": 1,
  "volumes": [
    { "type": "hdd", "id": "1", "name": "SD Card", "status": "ok",
      "capacity": 128000, "freeSpace": 96000 }
  ],
  "conclusion": "发现 1 个可用存储介质，可以尝试检索录像。"
}
```

**设备没有存储**

```json
{
  "success": true,
  "device": "192.168.1.100",
  "count": 0,
  "volumes": [],
  "conclusion": "设备没有报告任何存储介质 —— 这台设备本身不存录像（无 SD 卡、未接 NAS）。若录像实际在 NVR 上，请把 cameraIp 改成 NVR 的 IP 再检索。"
}
```

| 字段 | 说明 |
|---|---|
| `volumes[].type` | `hdd` / `sdCard` / `nas` / `volume` |
| `volumes[].status` | `ok` 表示可用；其它值可能是未格式化或损坏 |
| `volumes[].capacity` / `freeSpace` | 单位 MB |
| `conclusion` | **服务替你下的结论**，直接看这句 |

> **为什么这个接口重要**
>
> `/search` 返回 `invalidMemoryCardOrNAS`，就是设备在说"我没地方存录像"。
> 调一次 `/storage` 即可确认：
> - `count: 0` → 设备确实没有存储 → 录像应该在 **NVR** 上，把 `cameraIp` 换成 NVR 的 IP
> - `count > 0` 但 `status` 不是 `ok` → 存储介质未格式化或已损坏
> - 报 `notSupport` / `403` → 这台设备可能不是海康，或固件过旧

## 四、任务状态机

```
                  ┌──────────┐
   发起 /download │  queued  │  排队中（并发已满时等待）
                  └────┬─────┘
                       │ 调度器分配
                  ┌────▼─────┐
                  │ running  │  搜索录像段 → 逐段下载 → 转码 → 合并
                  └────┬─────┘
            ┌──────────┴──────────┐
       ┌────▼────┐          ┌─────▼────┐
       │  done   │          │  failed  │
       └─────────┘          └──────────┘
        可下载 mp4            看 error 字段
```

**进度百分比分布**

| 阶段 | percent |
|---|---|
| 受理 | `0` |
| 搜索录像段 | `2` |
| 找到段，开始下载 | `5` |
| 逐段下载 + 转码 | `5` → `70`（按段数递增） |
| 合并视频 | `96` |
| 完成 | `100` |

**并发与队列**

- 同时最多执行 **2 个**下载任务，超出的进入队列（`status: queued`）
- 通过环境变量 `RECORD_CONCURRENCY` 可调

## 五、错误码汇总

| 状态码 | 含义 | 常见原因 |
|---|---|---|
| `200` | 成功 | — |
| `204` | 预检请求成功 | CORS `OPTIONS` |
| `400` | 请求参数错误 | 缺少 `cameraIp` / `userName` / `password` / `start` / `end`；`end` 早于 `start`；请求体不是合法 JSON |
| `404` | 资源不存在 | `taskId` 不存在或已过期；文件名不合法或文件不存在 |
| `500` | 服务内部错误 | 未捕获异常，看服务日志 |
| `502` | 设备通信失败 | 设备不可达、端口错、账号密码错、无回放权限 |

**参数错误的 `error` 文案对照**

| 文案 | 触发条件 |
|---|---|
| `缺少 cameraIp 或 xaddr` | 既没传 `cameraIp`，`xaddr` 也解析不出 IP |
| `缺少 userName / password` | 用户名或密码为空 |
| `缺少 start / end` | 时间参数缺失 |
| `end 必须晚于 start` | 时间区间非法 |
| `时间格式无法识别: xxx（应为 "2026-10-15 08:00:00"）` | 时间字符串格式不对 |
| `请求体不是合法 JSON` | POST body 解析失败 |

**设备返回的海康错误码对照** —— 服务会自动翻成中文放在 `error` 字段，原始串保留在 `raw` 字段

| subStatusCode | 含义 | 怎么处理 |
|---|---|---|
| `invalidMemoryCardOrNAS` | 设备没有可用的录像存储 | 录像多半在 NVR 上 → 把 `cameraIp` 换成 NVR 的 IP；或给摄像头插 SD 卡 |
| `noRecord` | 该时间段确实没有录像 | 检查录像计划、循环覆盖、时间/时区 |
| `notFound` | 找不到对应资源 | 检查 `channel` / `stream` |
| `invalidTrackID` | 通道号无效 | 确认设备实际通道数（通道1主码流 = `101`） |
| `badParameters` | 参数不被设备接受 | 检查时间格式与 `tz` |
| `badAuthorization` | 认证失败 | 用户名密码错，或设备强制要求改弱密码 |
| `riskPassword` | 设备检测到弱密码 | 登录设备网页改密码 |
| `deviceBusy` | 设备忙 | 稍后重试 |
| `notSupport` | 设备不支持该操作 | 可能不是海康，或固件过旧 |

> 未收录的错误码会**原样返回**，不会丢信息。

## 六、完整流程示例

### 6.1 curl（Windows CMD）

```bat
REM ① 确认有没有录像
curl -X POST http://localhost:3001/search -H "Content-Type: application/json" ^
  -d "{\"cameraIp\":\"192.168.1.100\",\"isapiPort\":80,\"userName\":\"admin\",\"password\":\"admin123\",\"channel\":1,\"start\":\"2026-10-15 08:00:00\",\"end\":\"2026-10-15 09:00:00\"}"

REM ② 发起下载（记下返回的 taskId）
curl -X POST http://localhost:3001/download -H "Content-Type: application/json" ^
  -d "{\"cameraIp\":\"192.168.1.100\",\"isapiPort\":80,\"userName\":\"admin\",\"password\":\"admin123\",\"channel\":1,\"start\":\"2026-10-15 08:00:00\",\"end\":\"2026-10-15 09:00:00\"}"

REM ③ 轮询进度

### 6.3 JavaScript（完整封装）

```js
const API = 'http://localhost:3001';

/** 查询录像段 */
async function searchRecords(payload) {
  const res = await fetch(`${API}/search`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(payload),
  });
  const data = await res.json();
  if (!data.success) throw new Error(data.error);
  return data;                       // { count, segments, hint? }
}

/** 发起下载 */
async function startDownload(payload) {
  const res = await fetch(`${API}/download`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(payload),
  });
  const data = await res.json();
  if (!data.success) throw new Error(data.error);
  return data.taskId;
}

/** 查询进度 */
async function getProgress(taskId) {
  const res = await fetch(`${API}/progress?taskId=${taskId}`);
  return res.json();
}

/** 带进度回调的完整下载 */
async function downloadRecord(payload, onProgress) {
  const taskId = await startDownload(payload);

  return new Promise((resolve, reject) => {
    const timer = setInterval(async () => {
      let p;
      try {
        p = await getProgress(taskId);
      } catch (e) {
        clearInterval(timer);
        return reject(e);
      }

      onProgress?.(p);

      if (p.status === 'done') {
        clearInterval(timer);
        resolve(p);                                   // { file, size, ... }
      } else if (p.status === 'failed') {
        clearInterval(timer);
        reject(new Error(p.error));
      }
    }, 1500);
  });
}
```

**用法**

```js
const payload = {
  cameraIp: '192.168.1.100',
  isapiPort: 80,
  userName: 'admin',
  password: 'admin123',
  channel: 1,
  stream: 'main',
  start: '2026-10-15 08:00:00',
  end: '2026-10-15 09:00:00',
};

// 先查有没有录像
const { count, hint } = await searchRecords(payload);
if (count === 0) {
  console.warn('没有录像:', hint);
} else {

  });

  // 触发浏览器下载
  location.href = `${API}/file?name=${encodeURIComponent(result.file)}`;
}
```

## 八、附录

### 8.1 trackID 规则

服务内部按「通道号 × 100 + 码流位」换算设备侧的 trackID：

| 通道 | 码流 | trackID |
|:---:|---|:---:|
| 1 | 主码流 | `101` |
| 1 | 子码流 | `102` |
| 2 | 主码流 | `201` |
| 2 | 子码流 | `202` |

调用方**不用关心**这个，传 `channel` 和 `stream` 即可。

### 8.2 成品文件命名规则

```
ch{通道}_{开始日期}_{开始时间}_{结束时间}.mp4
```

示例：`ch1_20261015_080000_090000.mp4`
（通道 1，2026-10-15 08:00:00 → 09:00:00）

### 8.3 内部处理链路

```
① 查录像段   POST /ISAPI/ContentMgmt/search    → 拿到 playbackURI 列表
② 下载流     POST /ISAPI/ContentMgmt/download  → 海康私有 PS 流
③ 转 mp4     ffmpeg -i xxx.ps -c copy xxx.mp4
④ 多段合并   ffmpeg -f concat -c copy final.mp4
⑤ 返回文件   GET /file?name=xxx.mp4
```

**转码降级链**（自动重试，直到成功）：

1. `-c copy -tag:v hvc1` —— 无损封装，最快
2. `-c:v copy -c:a aac` —— 视频不转，音频转 AAC
3. `-c:v libx264 -preset veryfast -crf 23 -c:a aac` —— 完全转码，兼容性最好但吃 CPU

**单段 ffmpeg 超时**：30 分钟。

### 8.4 认证方式

服务对外**不鉴权**，任何能访问该端口的客户端都可调用。
生产环境请通过防火墙限制来源网段，或放在 Nginx 后面加认证。

设备侧使用的是 **HTTP Digest 认证**（不是 Basic），服务内部已处理。
